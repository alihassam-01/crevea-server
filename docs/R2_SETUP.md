# Cloudflare R2 assets

Set these values in the server environment. Keep the access key and secret server-side only:

```env
R2_ACCOUNT_ID=...
R2_ACCESS_KEY_ID=...
R2_SECRET_ACCESS_KEY=...
R2_BUCKET_NAME=crevea-assets
R2_PUBLIC_URL=https://cdn.example.com
R2_PRESIGN_EXPIRES_SECONDS=600
R2_MAX_IMAGE_BYTES=10485760
```

`R2_PUBLIC_URL` should be the public custom domain (or an R2 public bucket URL). The bucket must have a CORS policy allowing the frontend origin to `PUT` objects and read the response headers:

```json
[
  {
    "AllowedOrigins": ["http://localhost:3000", "https://your-production-domain.example"],
    "AllowedMethods": ["PUT", "GET", "HEAD"],
    "AllowedHeaders": ["Content-Type", "x-amz-checksum-sha256"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 600
  }
]
```

Apply the additive database migration before starting the server:

```bash
npm run db:deploy
```

Object keys are generated by the server and cannot be supplied by clients. Production assets use `production/...`; every non-production environment uses `dev/...`. Temporary source objects use `dev/temporary/...` or `production/temporary/...`; configure an R2 lifecycle rule to delete temporary objects after one day.
